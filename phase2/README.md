# Phase 2 — Provider Pilot Harness

Status: **Harness and adapters prepared. No external API was called. No image was
generated. No provider was selected or marked as passing.**

Phase 2 prepares a server-side provider pilot for the five representative
future garment cases from Phase 0, plus two sketch cases. The default mode is
mock/dry-run and makes no network calls, produces no images, and assigns no
quality scores.

The live game, AI Fashion Studio, wardrobe, and saved user data were not
modified. Phase 0 profiles remain `draft-needs-visual-signoff`. Generation scope
remains Clothes → Upper/Lower only; fitting, mesh warping, and wardrobe
registration are not implemented.

## 3. Prompt policy

`server/phase2/prompt-builder.js` builds the prompt server-side from structured
case data. The safety/style rules are appended for every provider and cannot be
removed by client text:

- one single garment only;
- front view, centered, full garment visible;
- garment only: no person, body, mannequin, hanger, background, floor, text, or
  watermark;
- no outfit, no multiple garments;
- transparent background with clean alpha edges;
- flat 2D chibi fashion illustration, not photorealism.

Sketch cases add:

- the attached image is the authoritative shape guide;
- preserve neckline, waistline, sleeve length, hem, leg width, and silhouette;
- clean rough construction lines and canvas marks;
- do not add a person or copy the reference doll.

The report stores only the prompt length and SHA-256, not the full prompt.

## 4. Evaluation rubric

Every case result contains these fields. Scores are intentionally `null` until
a human reviewer fills them. Mock mode never assigns scores.

| Report field | Criterion |
|---|---|
| `garmentOnlyCompliance` | One garment only; no person/body/mannequin/hanger/background; full garment visible |
| `transparencyAndEdgeCleanliness` | Real alpha PNG; transparent background/corners; clean edges; minimal halo/fringe/holes |
| `styleConsistency` | Flat 2D chibi fashion style; crisp outlines, soft cel shading, readable shapes |
| `sketchFidelity` | Sketch silhouette and key details preserved; not applicable to concept cases |
| `silhouetteAndShape` | Correct, readable garment silhouette and proportions |
| `fittingSuitability` | Centered/margined/front-facing; separable sleeves/legs/hems; plausible later affine fit |

Scale: 0–4. The pilot report does not claim automatic vision scores. Real
outputs require human review; `analyze_outputs.py` adds automated PNG/alpha
measurements only.

## 5. Mock mode

Default command:

```bash
node phase2/pilot-runner.cjs
```

Equivalent explicit command:

```bash
node phase2/pilot-runner.cjs --mode=mock --provider=mock
```

Mock mode:

- does not read provider keys;
- does not call `fetch`;
- does not create images;
- writes `report.json` and `report.md` with `simulated: true`;
- labels every case `status: "simulated"`;
- leaves latency and estimated cost `null`;
- leaves every quality metric `null` with
  `simulated_not_evaluated` (or `not_applicable` for sketch fidelity on concept
  cases);
- never contains a "passed" claim.

Run only one case:

```bash
node phase2/pilot-runner.cjs --case=future-fullbody-dress
```

Choose an output directory:

```bash
node phase2/pilot-runner.cjs --out=phase2/output/mock-check
```

Output is ignored by git via `phase2/.gitignore`.

## 6. Real pilot — exact requirements

Real mode is deliberately blocked unless **all** of these are true:

1. `--mode=real` is passed;
2. `--provider=openai` or `--provider=replicate` is passed;
3. `PHASE2_PILOT_CONFIRM_COST=YES` is set;
4. the selected provider's server-side credentials and model settings are set;
5. the adapter is implemented and configured.

The runner checks these before any provider call. Without them it exits without
network access.

### OpenAI

Required server-side environment:

```text
PHASE2_PILOT_CONFIRM_COST=YES
OPENAI_API_KEY=<server-side key>
OPENAI_IMAGE_MODEL=<current image model id>
```

Optional:

```text
OPENAI_IMAGE_SIZE=1024x1024
OPENAI_IMAGE_QUALITY=<model-supported quality>
PHASE2_PRICE_PER_IMAGE_USD=<your own estimate for the report>
```

Command:

```bash
PHASE2_PILOT_CONFIRM_COST=YES \
OPENAI_API_KEY="<set in your shell, not in chat>" \
OPENAI_IMAGE_MODEL="<current model id>" \
node phase2/pilot-runner.cjs --mode=real --provider=openai \
  --out=phase2/output/openai-pilot
```

The prepared adapter uses `/v1/images/generations` for concept cases and
`/v1/images/edits` for sketch cases, requests PNG + transparent background, and
records latency plus provider request ID. Verify the selected model's current
parameters before running.

### Replicate

Required server-side environment:

```text
PHASE2_PILOT_CONFIRM_COST=YES
REPLICATE_API_TOKEN=<server-side token>
REPLICATE_MODEL=<owner/name>    (or REPLICATE_VERSION=<version id>)
```

Optional model-input mapping:

```text
REPLICATE_SKETCH_INPUT_KEY=image
REPLICATE_INPUT_JSON={"aspect_ratio":"1:1"}
REPLICATE_POLL_ATTEMPTS=30
REPLICATE_POLL_INTERVAL_MS=1000
PHASE2_PRICE_PER_IMAGE_USD=<your own estimate for the report>
```

Command:

```bash
PHASE2_PILOT_CONFIRM_COST=YES \
REPLICATE_API_TOKEN="<set in your shell, not in chat>" \
REPLICATE_MODEL="<owner/model>" \
node phase2/pilot-runner.cjs --mode=real --provider=replicate \
  --out=phase2/output/replicate-pilot
```

Replicate models do not share one input schema. Review the selected model's
input fields and transparency behavior before the real pilot. The adapter does
not hardcode a model or version and does not claim transparency support.

### Stability AI

The registry keeps `stability` reserved with `implemented: false`. Adding it
later means implementing the same interface and adding server-side env names;
the runner/report schema do not need redesign.

### Cost and latency

- Latency is measured only for real calls.
- Estimated cost is `null` unless the provider returns a cost or
  `PHASE2_PRICE_PER_IMAGE_USD` is explicitly set. The harness does not invent
  prices.
- The report marks partial cost estimates rather than implying a complete total.
- No provider call is made by tests or mock mode.

## 7. Sketch fixtures and analysis

Generate the two synthetic 800×800 transparent sketch fixtures:

```bash
python -I phase2/make_sketch_fixtures.py
```

Analyze a real report's PNG artifacts:

```bash
python -I phase2/analyze_outputs.py --report phase2/output/openai-pilot/report.json
```

This writes `report.automated.json` next to the report with dimensions, alpha
bounding box, transparent/semi-transparent/opaque ratios, and corner
transparency. These are proxies only; edge cleanliness, style, sketch fidelity,
and fitting suitability remain human review criteria.

Analyze a single image:

```bash
python -I phase2/analyze_outputs.py --image clothes/gömlek1.png
```

## 10. Remaining requirements for the real pilot

1. Approve a provider and a specific model, plus a budget cap.
2. Provide credentials through server-side environment variables, never chat or
   client code.
3. Replace the two synthetic sketch fixtures with real Draw Your Own exports if
   the goal is real sketch-fidelity evidence.
4. Verify the chosen OpenAI model's current image/edit parameters, or the chosen
   Replicate model's input schema and transparency behavior.
5. Run the real pilot in a controlled environment with
   `PHASE2_PILOT_CONFIRM_COST=YES`.
6. Run `analyze_outputs.py`, then complete the human-review scores.
7. Compare providers using the same seven cases and rubric. No provider has
   passed yet; no provider is selected.
8. Keep generation disabled in the public app until the pilot and fitting work
   are approved.
